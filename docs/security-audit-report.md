- **Branch**: `security/full-stack-audit-hardening`
- **Target Baseline**: `v1.0.0` (Windows x64 `.NET Framework 4.8` WinForms + WebView2 portable desktop utility)
- **Audit Scope**: Full line-by-line audit across all 4 architecture layers:
  1. **Layer 1 — Host, Process Lifecycle, IPC & Build** (`Host/*.cs`, `app.manifest`, `build.bat`, `can-i-delete.csproj`)
  2. **Layer 2 — Scan, Deletion, Recycle Bin & Native P/Invoke Engine** (`Engine/*.cs`)

- **Final Remediation Status**: **50 / 50 Findings Remediated & Verified (100%)**

## 1. Executive Summary & Severity Breakdown

Because **按平 (`can-i-delete`)** runs as a portable application (frequently extracted to user-writable directories such as Desktop or Downloads) with on-demand UAC elevation (`asInvoker` -> `runas`), every unprivileged-to-elevated trust boundary — inherited environment variables, DLL search paths, portable `data/` and `ui/` directories, NTFS reparse points/junctions, handle-bound file deletion, and WebView2 host-to-UI IPC — is a direct privilege or data-integrity boundary.
